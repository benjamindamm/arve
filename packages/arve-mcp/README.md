# Arve MCP

Read a published Arve UX handbook from a static website through MCP. The website needs no application server. This package runs locally and contains no handbook or company data.

## Install from GitHub

Download the npm `.tgz` from [Arve MCP 0.1.0](https://github.com/benjamindamm/arve/releases/tag/mcp-v0.1.0), then install:

```sh
npm install -g ./benjamindamm-arve-mcp-0.1.0.tgz
```

Alternatively let your MCP client run the versioned release directly:

```json
{
  "mcpServers": {
    "arve": {
      "command": "npx",
      "args": [
        "-y",
        "--package=https://github.com/benjamindamm/arve/releases/download/mcp-v0.1.0/benjamindamm-arve-mcp-0.1.0.tgz",
        "arve-mcp",
        "--base-url",
        "https://benjamindamm.github.io/arve/"
      ]
    }
  }
}
```

Use your own site root, including any project prefix. Do not append `/mcp`. Alternatively set `ARVE_BASE_URL`. Requires Node.js 22 or later on the agent's machine. Arve's static host does not need Node.js.

For a globally installed package, use `command: "arve-mcp"` with `args: ["--base-url", "https://example.org/arve/"]`.

## GitHub Packages

The npm package is also published at `npm.pkg.github.com`, associated with `benjamindamm/arve`. It is not published on npmjs.com. GitHub's npm registry requires authentication even for public packages. If you prefer no registry login, use the public release asset above.

After authenticating to GitHub Packages with a `read:packages` token and configuring `@benjamindamm:registry=https://npm.pkg.github.com` in your npm settings:

```sh
npm install -g @benjamindamm/arve-mcp@0.1.0
```

See [GitHub's npm registry documentation](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-npm-registry). Do not commit tokens to your repository.

## What an agent can read

The site must contain `arve-data/current.json`, generated by Arve's static build. Any HTTP(S) static host works. Server-hosted Arve installations retain their HTTP MCP endpoint; this package uses local stdio instead.

The tools match Arve's server: design systems, hierarchy, search, published pages and sections, component guidance and platform evidence, linked contract files, portable contract skills and Arve authoring skills. Color comparisons retain their text fallback and MCP App resource. Contracts are optional.

Start with `list_design_systems`, then `list_documentation_tree` or `search_documentation`. Follow returned read arguments and continuations. Tool descriptions distinguish published rules, examples and implementation evidence. The package cannot edit or publish CMS content.

One session pins one export revision. Resources load on demand and must match its SHA256 manifest. Reconnect to see a new deployment. Missing old releases fail explicitly; the client never silently mixes releases. Trust in the publication comes from the configured host and HTTPS.

No arbitrary file or URL reads, redirect following, CMS credentials or source-repository access. Sites requiring interactive login are not supported by this version.

## Build and release in the Arve repository

```sh
npm ci
npm run build:mcp
npm run build:static
npm run check:mcp:static
npm run pack:mcp
```

The `.tgz` contains the executable and this guide, without Payload, Next.js, a database or design-system content. Its runtime dependencies are declared in the npm manifest.

Run **Release Arve MCP on GitHub**, select `main`, set `publish=true` and enter the exact package version. The workflow validates and packs the package, publishes it to GitHub Packages with the repository's `GITHUB_TOKEN`, then creates `mcp-v<version>` with the same `.tgz` asset. No npmjs account or stored personal publishing token is needed. Versions cannot be overwritten.

A new GitHub package is initially private. Set its visibility to public in its package settings if desired; the release asset is public when the repository is public. `UNLICENSED` preserves the existing rights until an explicit license is chosen.

# Command · semantische Komponentenreferenz

Filter and invoke application commands while distinguishing search text, active command highlight and actual execution.

Status der neuen Domänenmigration: **complete** im begrenzten Referenzumfang. Stabile Teile, tatsächlich passende Source-Selektoren, semantische Tokenwerte und nutzbare Zustands-Fixtures wurden mit dem normalen Komponentenprüfpfad und der echten React-Verwendung geprüft. [Browsernachweis](../../validation/semantic-pickers-browser-run.json); keine allgemeine Anwendungsfreigabe.

Command is cmdk, not a Menu or selected-value picker: Input query, active option highlight and Item onSelect execution remain distinct. Native command frame 14px corners/4px inset are retained with explicit 28px minimum row,36px search role,300px scroll maximum and 384px palette maximum. Actual Input wraps InputGroup and addon; its command-input slot needs explicit flex:1 and nowrap on that delegated group, because generic InputGroup control-slot rules do not target cmdk Input. This preserves the chosen 36px search row rather than wrapping the glyph onto a second row. List is listbox, Item is option, and cmdk Group heading selector is a stable upstream DOM attribute rather than a source-node identity. Highlight uses actual data-selected; optional caller data-checked check glyph is separate and source shortcut presence hides the glyph. No keyboard binding is created by shortcut text. The source CommandDialog places registered title/description siblings before Popup; this reference mounts on opening/unmounts after close completion, hides only that header visually and preserves its actual naming IDs. Modal focus/close/cancellation remain delegated to Dialog; command-specific popup has zero inset and one-third physical centered placement, with narrow viewport bounded by Dialog. The explicitly enabled Close button retains its delegated physical-right placement, so the search input reserves 40px physical-right padding in both text directions. Theme and direction are application document context in this adapter because CommandDialog exposes className but no Popup dir/data-theme prop; leading CSS remains component-owned and source-independent. No fake aria-modal attribute or invented Root disabled/value veto is added. No-results text is an explicit readable status, and caller chooses to close palette after execution.

Command wraps cmdk1.1.1. Root value/defaultValue is the active/highlighted item string, not a completed operation; Root onValueChange is that highlight callback. In this pinned implementation that callback is emitted in the controlled Root path, so this reference supplies controlled value/onValueChange and always mirrors the returned value. This is not a cancellable request; ignoring it is not promised to veto cmdk internal transient highlight. Item onSelect(value:string) is the actual invocation callback. Input has its own value/onValueChange(search:string). Item values and keywords are trimmed; supply stable unique values rather than relying on changing text content. Default fuzzy filtering/scoring sorts matches; shouldFilter=false transfers filtering/rendering to the caller, forceMount bypasses an item/group filter, loop defaults false, disablePointerSelection controls pointer highlight and vimBindings defaults true. Disabled items are excluded from enabled navigation/activation; there is no whole-Root disabled prop. List is listbox, input is combobox with active-descendant relation, items are option (not menuitem), group headings supply source relations. Empty is presentation; this reference supplies explicit status text for no results. Shortcut is only displayed text and registers no global shortcut. CommandDialog composes the existing Base UI Dialog contract, defaults title Command Palette/description Search for a command to run and showCloseButton=false. Its title/description are registered sibling parts before DialogContent; this reference mounts that composed actor on opening and removes it after onOpenChangeComplete(false), avoiding stray closed-state sibling headings while retaining the source closing lifecycle. The reference explicitly sets showCloseButton=true, so cancel is available without a physical Escape key or executing a command. It does not register a global Meta+K listener or automatically close after onSelect; caller invocation may close it explicitly.

Inline cmdk uses Up/Down, Home/End, Enter invocation and source Ctrl+n/j/p/k bindings when vimBindings=true. Typing filters and may change highlight but never executes a command. Native input focus stays in the combobox while active-descendant identifies the selected option. Inline Escape does not automatically close or clear the component. CommandDialog delegates initial/return focus, modal ownership and Escape/cancellation to the actual Dialog primitive; the reference provides an explicit external Open command palette button and closes on successful caller action. Search, highlight, action and Dialog open are independent authorities.

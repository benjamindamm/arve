# Read contracts and assess UX suitability

1. Read the selected component definition and its bound sources. Keep CEM interface, DTCG/CSS visual rules, SCXML behavior, and HTML/ARIA accessibility distinct. Preserve identifiers, states, types and units across these boundaries.
2. Establish the user task, input/output value contract, context and accessibility needs. Unknown facts are unknown, not false. Ask when a missing fact changes the choice.
3. Follow optional UX and selection bindings only when present. Compare declared capabilities with the task. Separate source-backed rules, derived judgments, assumptions and observations. Do not invent a selection policy or import another library's defaults.
4. Missing domains, contradictory claims and open coverage criteria prevent claims of completeness. Historical receipts describe their original sources, not this export or a browser implementation. Manifest hashes establish file integrity only.
5. State the library and export revision, component IDs, actual evidence, limitations and target checks still required. Never equate draft coverage, static previews or historical passes with general accessibility, usable UX or runtime acceptance.
6. Reading this package requires only text/JSON/XML/CSS readers. No source repository is needed. Authoring, executable validation and rendering require a separately supplied toolchain; none is bundled or promised here.

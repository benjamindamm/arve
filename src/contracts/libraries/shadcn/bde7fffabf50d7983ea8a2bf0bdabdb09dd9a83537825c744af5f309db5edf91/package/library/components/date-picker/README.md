# DatePickerReferenceComposition · gebundene Quellenreferenz

Select actual local calendar dates with distinct selected value, keyboard focus and displayed month. Compose the date calendar inside an independently controlled named Popover.

Offizieller shadcn-Commit `45bbf9ba23c9c0f63d38887947e5fb06f59c7da3`. [Unveränderte Quellen und Pakethashes](../../sources/manifest.json), [Wrapper-/Rezeptinventar](../../sources/react-api-inventory.json).

Calendar forwards the full React DayPicker 9.14.0 discriminated prop union (mode absent|single|multiple|range, required variants) plus buttonVariant. shadcn defaults showOutsideDays=true, captionLayout=label, buttonVariant=ghost; locale, formatters, classNames and components are explicit overrides. CalendarDayButton is the exported native shadcn Button adapter, attempting to synchronize focus when modifiers.focused changes, but the pinned wrapper omits attaching its ref: raw keyboard focus is broken while internal focused modifiers advance; data-day is locale-formatted, never a stable ISO identifier. DayPicker selection is Date|Date[]|DateRange|undefined according to mode/required. Supplying onSelect makes the selected prop authoritative even when undefined; without onSelect the primitive owns internal selection. onSelect(selected,triggerDate,modifiers,event) is separate from onDayClick(date,modifiers,event); the source calls selection first, onDayClick afterward. DayPicker itself prevents default and propagation on day click; defaultPrevented is not a generic veto/cancellable eventDetails API. Optional single may clear by selecting the same date; required single does not clear. Multiple min/max and range min/max/excludeDisabled/resetOnSelect are source algorithms, not assumed to be the same toggle. excludeDisabled resets a candidate range crossing a disabled date to its new start. disabled is a Matcher or Matcher[], hidden differs from disabled, and no synthetic root disabled boolean is invented. Displayed month/defaultMonth/onMonthChange is independent from selected date; startMonth/endMonth bound month navigation, not selection by themselves. Selection need not submit a form. Root is a named div by default, each month table is the source named grid, with native day buttons, registered roving tabIndex and labelled selected/today dates. Noninteractive mode omits day buttons. Footer is the primitive polite status; essential validation instructions remain persistent outside it. Date Picker is explicitly the documented Popover + Calendar composition, with no upstream DatePicker root. The basic official onSelect only sets date and leaves the popup open; no automatic close-on-select is invented. Trigger text includes the current formatted date or Pick a date. Popover nonmodal dialog naming, Escape, outside dismissal, controlled cancellation, Presence and focus restoration retain the already complete Popover contract. Range and date-of-birth presets are optional Calendar compositions, not a new Root value type.

The explicit reference components.DayButton adapter forwards an attached ref through exported CalendarDayButton rest props and focuses it on modifiers.focused, preserving original styling and handlers. This repairs the observed pinned source omission; raw wrapper behavior is preserved as a negative browser regression. The active day has one tabIndex=0; source focus navigation skips disabled/hidden dates. Left/Right move a day (RTL reverses), Up/Down a week; Shift+Left/Right move a month and Shift+Up/Down a year. PageUp/PageDown move month, Shift adds year; Home/End move to week boundaries. Native Enter/Space selects the focused eligible day. Keyboard focus can move without selection. Navigation arrows have source native disabled boundaries. Calendar alone has no Escape dismissal or focus trap. Caller-provided components/labels must preserve the source refs, event handlers, names and native semantics.

Reference locale is en-US with local dates (no UTC string conversion), fixed November2026 and today November21, selected November12, disabled November13, November–December navigation bounds. The attached focus-ref components.DayButton adapter is an explicit caller repair, not falsely attributed to unchanged upstream. These concrete values and Delivery date name are chosen reference usage, separate from native FIG visual samples. Single and range are exercised, required/multiple remain exact source-described API variants. A typed date input, time, natural-language parsing, remote availability and submit persistence are separate optional application compositions, not promised Calendar or DatePicker exports.

SCXML observes actual source callbacks, retaining original Date/range/modifiers/event objects. It delegates date normalization, disabled matching, range construction and detailed focus to pinned DayPicker; no fake DatePicker export, generic selection event or defaultPrevented veto is added. Popover remains an independent completed actor. HTML is an actual pinned wrapper SSR projection plus explicitly named caller composition.
